# 2026-07-31 工作日志

## 社区角色卡下载失败排查

- 用户报告"角色卡下载失败"，定位为社区页（CommunityTab）下载链路。
- 实测线上服务端 `https://community.neural-node.xyz` 全链路正常：health/deep、列表、下载登记（POST /api/cards/:id/download）、文件拉取（GET /cards/...）均 200；Tauri 来源（`http://tauri.localhost`、`tauri://localhost`）CORS 预检通过。
- 发现缺陷一（已修复）：8 个语言文件的 `community.download_failed` / `upload_failed` / `load_failed` 模板均缺少 `{error}` 占位符，代码传入的真实错误被吞掉，用户只能看到"下载失败，请稍后重试"。已补齐 24 处，`npm run check:i18n` 通过。
- 发现缺陷二（未修复，需服务器操作）：开发模式 `tauri dev` 的前端来源是 `http://127.0.0.1:3000`（vite dev，见 src-tauri/tauri.conf.json devUrl），不在云端 `CORS_ALLOWED_ORIGINS` 白名单内，开发态社区接口（含下载）全部被浏览器拦截。需在 VPS 的 `.env` 中追加该来源后重启服务。
- 若用户在正式 App 中遇到失败，最可能是设备到 Cloudflare 的网络问题；修复后的报错会显示具体原因（如 HTTP 状态码或 Failed to fetch）。

## 正式 APK 下载失败根因确认（已实锤）

- 用户反馈正式 APK 点击下载失败，但 PC 脚本上传下载均正常。
- 实测对比：`/api/` 路由（Rust CorsLayer）返回 `access-control-allow-origin`；`/cards/` 静态文件由 Nginx 直接发文件，**无 ACAO 头** → WebView `fetch()` 被 CORS 拦截（TypeError: Failed to fetch）。
- 现象自洽：列表（/api/）正常、封面 `<img>` 不受 CORS 约束能显示、仅下载失败；PC 脚本不强制 CORS 所以正常。
- 处置：新增 `cloud/minimal-community/deploy/nginx.conf.example`（/cards/ location 内按 Origin 白名单返回 ACAO），并在云端 README 部署章节补充 CORS 要求。服务器侧改 Nginx 后 reload 即可，APK 无需重装。
