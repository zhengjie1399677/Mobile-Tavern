# Mobile Tavern — 长期项目笔记

## 产品战略（用户明确表达，影响所有优先级判断）
- **核心愿景**：在 Mobile Tavern 里支撑一个"真正的开放世界"，而非做一个垂直的单角色 App。
- **刻意取舍**：选择做"兼容支撑底座"而非更容易做、也更好宣传的垂直单角色 App；**先堆功能/世界，后补充打包与宣传**。
- **底座与开放世界的等价性**：开放世界要求内核保持通用、零侵入——`COMPAT-DATA` / `ARCH-KERNEL` 等铁律正是"开放"的代价。一旦让某角色卡/插件的规则漏进 kernel，世界就退化成垂直 App。用户拒绝让任何单一世界规则污染内核，故此"很少优先做吸引目光的事"。
- **对协作的含义**：
  - "造世界"的事（功能、插件、内容）由用户主导、用户擅长，团队按需辅助加厚。
  - "开门"的事（`.mtplugin` 打包、host 存档桥、依赖修复、商店/社区分发）机械、可委派、但不做则世界无法被进入——属 P0 但不必占用用户精力，可派工程师快速模式推进。
- **expedition-inn（远征余响）定位**：是活在开放世界里的"内容插件"，不是独立垂直产品，故无需单独做营销包装；它直接复用已做好的 LLM 桥接与数据驱动底座，故长出玩法很快。当前硬缺口仅为未打包为 `.mtplugin`（无 manifest、无打包脚本、存档未走 host 桥）。

## 沟通偏好
- 用户用中文交流；回答用简体中文。
- 用户能看懂深度技术讨论，可直接谈架构/边界/依赖，无需过度铺垫。
- 用户表态"懒得弄"商店/社区等运营类事务——默认不主动推进分发，除非用户要求。
