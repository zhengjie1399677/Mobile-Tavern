## 二、已修复

### T3 配置与秘密 / T5 安全

1. **`server.ts`：不再把原始用户凭证写入日志**
   - 问题：`/check-update` 请求日志原样输出 `userCredential`，属于可关联用户信息，存在日志泄露风险。
   - 修复：仅记录 `credentialLength`，不再输出凭证内容。
   - 验证：类型检查通过；`testServerLogDesensitization` 及全量测试通过。

2. **`src/utils/keyManager.ts`：不再把解密密钥前缀写入日志**
   - 问题：`getTrialKey()` 成功日志输出 `decryptedKey.substring(0, 10)`，泄露密钥前缀。
   - 修复：仅记录 `decryptedKey.length`。
   - 验证：类型检查通过；全量测试通过。

3. **`server/config.ts`：生产环境拒绝开发默认 HMAC 签名密钥**
   - 问题：生产模式对 `AES_ENCRYPT_KEY` 会拒绝开发默认值，但 `HMAC_SIGN_KEY` 只检查长度，未拒绝开发默认值，存在配置分轨不一致。
   - 修复：生产模式若 `HMAC_SIGN_KEY` 为开发默认值 `default_local_hmac_sign_key_123456` 则快速失败，与 AES 规则一致。
   - 验证：`tests/vitest/configuration.test.ts` 新增用例，4 用例全部通过。

4. **`src/utils/keyManager.ts`：401 时清除失效的内存 token 缓存**
   - 问题：`getTrialKey()` 收到 401 时删除的是从未写入的 `localStorage["mt_auth_token_cache"]`（死代码），而真实缓存是模块级内存 `tokenCache`；结果是已被服务端拒绝的 token 仍会被复用，直到临近过期才刷新。
   - 修复：401 时置空 `tokenCache`，移除无效的 localStorage 删除调用。
   - 验证：类型检查通过；全量测试通过。

5. **`server.ts`：修复 `/api/check-update` 时间戳校验可被 NaN 绕过**
   - 问题：`Number(timestamp)` 对非数字字符串得到 `NaN`，`Math.abs(Date.now() - NaN) > 5 分钟` 恒为 false，从而绕过 5 分钟新鲜度校验；另外 `clientVersion` 若为数字会触发 `v.split` 崩溃。
   - 修复：先校验 `Number.isFinite(ts)`，并将 `clientVersion` 显式转字符串。
   - 验证：类型检查通过；全量测试通过。

6. **`cloud/minimal-community/src/main.rs`：管理令牌改用常数时间比较**
   - 问题：`is_admin` 用 `supplied == expected` 比较管理令牌，`str::eq` 逐字节提前退出，存在时序侧信道。
   - 修复：新增 `constant_time_eq`（长度相等后逐字节 XOR 累计），不新增依赖。
   - 验证：`cargo check` 通过。

### T4 数据与迁移 / 分支数据完整性

7. **`DatabaseService.ts`：回溯分支改用 messages Store 完整历史**
   - 问题：`createBacktrackBranch` 直接切 `sourceSession.messages`，但会话消息是懒加载的（每页 50 条）；长会话未加载全部历史时，新分支会丢掉早于已加载页的消息。
   - 修复：从 messages Store 读取完整历史再截断；store 无记录时回退到内存数组（兼容测试 mock）。
   - 验证：类型检查通过；全量测试通过。

8. **`indexedDbMemoryStore.ts`：重发分支清扫起点改为被移除消息的最小 turnIndex**
   - 问题：`replaceSessionBranch` 用 `session.messages.length - newMessages.length` 推导清扫下界；懒加载时该数组只含最近一页，下界偏小，会把早于已加载页的合法历史一并删除（长会话重发时反复丢数据）。
   - 修复：
     - 有被移除消息时，下界改为“被移除消息的最小 turnIndex”；
     - 无被移除消息时（重发最后一条用户消息），下界改为“store 当前最大 turnIndex + 1”，只追加不删除，避免把该用户消息连同更早历史一起误删。
   - 验证：`turnIndexConsistency` 及全量测试通过。

9. **`indexedDbMemoryStore.ts`：批量同步消息保留 system 角色**
   - 问题：`syncSessionMessages` 把非 user 一律写成 `assistant`，`system` 消息在分支创建/导入时被静默降级为 `assistant`。
   - 修复：保留 `user/system/assistant` 三态。
   - 验证：类型检查通过；全量测试通过。

10. **`archival.ts`：故事年表边界改为按被移除消息过滤**
    - 问题：`reconcileSummaryBoundary` 依据内存中的 `messages` 过滤摘要卡；懒加载下内存只有最近一页，长会话重发/删除时会把“边界在更早消息上的摘要卡”一并误删，导致故事年表整段丢失。
    - 修复：改为按 `removedMessageIds` 过滤，仅移除边界落在被删除/覆盖分支的卡片；边界回退到最后一张保留卡片。
    - 验证：新增懒加载回归用例；`foldHelpers` 及全量测试通过（vitest 659）。

11. **`MemorySummary.ts`：摘要输入保留 system 角色**
    - 问题：从 messages Store 装载后把 `system` 一律映射为 `assistant`，系统消息会以角色名混入摘要输入。
    - 修复：保留 `user/system/assistant` 三态。
    - 验证：类型检查通过；全量测试通过。

12. **`pipelineHelpers.ts`：记忆抽取改用消息真实 turnIndex**
    - 问题：`scheduleExtraction` 传入 `messages.length - 1/-2`（懒加载内存数组下标），而 store 里消息是绝对 `turnIndex`；长会话里两者不一致，导致记忆片段/事实的 `sourceTurn*`、`validFromTurn` 错误，重发清扫时漏删或误删旧分支记忆。
    - 修复：按 `msgId` 从 memory storage 读真实 `turnIndex`，失败时回退数组下标。
    - 验证：类型检查通过；全量测试通过。

13. **`useRerollMessage.ts`：重发成功路径增加 requestId 守卫**
    - 问题：重发的错误/中断路径已有 `requestId` 守卫，成功路径缺失；低概率下被新请求取代的旧重发仍会提交结果，表现为“连续发两条”。
    - 修复：流式结束后若 `requestId !== activeRequestIdRef.current`，丢弃本次结果。
    - 验证：类型检查通过；全量测试通过。
