# Mobile Tavern 竞品分析报告

> 分析日期：2026-08-05 ｜ 分析对象：AI 角色扮演（Roleplay）客户端赛道 ｜ 分析视角：Mobile Tavern 差异化定位
> 数据来源：公开资料检索（官网/评测/GitHub/应用商店），非一手用户调研。

---

## 0. 摘要（TL;DR）

Mobile Tavern 处在一条"夹缝"里，但这条夹缝是真实存在且未被填满的：

- **上游兼容生态**（SillyTavern / TavernAI）功能最强，但**没有官方原生移动端**——手机只能用浏览器访问 PC 实例或 Termux 硬跑，痛点明确且被官方文档和用户反馈反复证实。
- **下游商业 App**（猫箱 / 星野 / 筑梦岛 / Character.AI）移动体验好、内容生态强，但**黑盒、云端存储、不可控 Prompt、角色卡不可导出**，与"酒馆核心用户"（角色卡资产持有者、深度自定义玩家）的需求根本冲突。
- **开源 Web 端**（Agnaistic / RisuAI）能力不错，但**仍是浏览器体验**，且兼容度、记忆深度、游戏化追踪均不如 Mobile Tavern 的既定能力。

**结论**：Mobile Tavern 的"移动端原生 + SillyTavern 兼容底座 + 100% 离线"组合，在 2026 年当前仍无直接对手。差异化方向应聚焦三件事：**兼容做深（数据可带走）、原生做透（体验代差）、游戏化做轻（时间线/RPG 追踪）**，而不是追着商业 App 做内容生态。

**矩阵读出的三个结构性事实：**

1. **没有第二款产品同时满足"● 角色卡兼容 + ● 原生移动 + ● 离线"**。ST 兼容但移动弱；Agnaistic/RisuAI 兼容但浏览器；商业 App 移动强但完全封闭。
2. **Prompt 深度控制是商业 App 与开源生态之间不可跨越的鸿沟**。酒馆核心用户的资产（角色卡、世界书、预设、regex）在商业 App 里无法落地，这是 Mobile Tavern 的天然用户池。
3. **游戏化追踪（好感度/道具/心境）在所有竞品中都是空白**——ST 靠扩展补、商业 App 是剧情包装而非系统化状态追踪。

## 3. 用户评价 / 口碑汇总

### SillyTavern（移动端痛点被反复证实）
- 官方 FAQ 明确：iOS/iPadOS 只能浏览器访问其他设备实例；Android 用 Termux 原生运行且**标注"不受官方支持，无法保证正常工作"**。
- GitHub Issue #46（iOS 竖屏无法滚动、按钮触控失灵）是长期存在的历史问题，横屏/竖屏行为不一致。
- 第三方评测（dev.to）：Termux 方案受 Android 12+ **Phantom Process Killer 限制**（后台 Node 子进程被系统静默杀死）、锁屏吞会话、重启回退；社区常见建议是"租 VPS 或放弃"。
- 结论：**"在手机上稳定跑酒馆"至今没有官方解法**，第三方 SillyDroid 等 APK 多为搬运封装，维护与安全质量存疑。

### Agnaistic
- 优点：现代界面、角色卡兼容（ST/Tavern 格式）、Embeddings 记忆、群聊、chat graph 可视化、内置生图。
- 缺点（用户反馈）：部分功能"感觉未完成"、高级视图学习曲线陡、**依赖外部模型提供商**、分享能力弱、移动端仍偏浏览器体验。
- 项目体量：GitHub ~736 stars / 138 forks，社区活跃度中等，与 ST（200+ 贡献者、万级 star）不在一个量级。

### RisuAI
- 核心口碑：**长对话记忆保持优于基础 Tavern 配置**，适合长剧情驱动；但功能面窄、社区小、性能依赖所选后端。

### 国内商业 App（猫箱/星野/筑梦岛）
- 共性好评：移动体验顺滑、语音强、内容生态丰富、即时满足（抖音式滑动匹配）。
- 共性差评/隐忧：
  - **人设崩塌（OOC）**：长对话后逻辑混乱，商业 App 无法通过用户侧 Prompt 工程缓解（黑盒）。
  - **隐私**：对话全部服务器存储；评测普遍提示"不要在对话中透露真实信息"。
  - **配额**：免费额度受限（筑梦岛约 50 条/日），重度使用强制订阅。
  - **数据封闭**：角色卡/聊天记录不可导出，用户资产被锁定在平台内。
- 行业级风险（媒体分析）：内容合规与未成年人保护红线、情感依赖伦理争议——监管随时可能收紧。

## 5. 推荐差异化方向（附理由与验证建议）

### 方向一（主攻）：把「移动端原生 ST 兼容容器」做成事实标准
- **做什么**：兼容面继续扩——charx 格式、更多 ST 预设/扩展导入路径、regex 脚本子集、对话历史 ST 格式互导；把"导入失败"和"兼容警告"的降级体验打磨到零挫败。
- **为什么**：G1 是唯一被官方亲口确认的空白（ST 官方 FAQ 白纸黑字）。谁先占据"手机上稳定的酒馆"心智，谁就是该细分的事实标准。
- **验证**：发布到 GitHub Releases + 社区渠道后，观察"从 Termux/浏览器迁移"的用户反馈与回访；把 `import 成功率` 和 `兼容警告率` 作为核心指标埋点。

### 方向二（护城河）：数据所有权叙事 —— "你的角色卡永远属于你"
- **做什么**：把离线 + 备份 v4 + 脱敏能力产品化：一键全量导出/导入、加密备份、跨设备迁移向导；公开承诺"无服务器、无遥测上传聊天内容"。
- **为什么**：商业 App 的隐私投诉与数据封闭是持续性痛点，且监管收紧只会放大；开源社区（ST/Agnaistic）用户本就反感云端锁定。
- **验证**：README/首页强化该叙事；社区问卷问"选择 Mobile Tavern 而非商业 App 的原因"，验证隐私是否为 Top 动机。

### 方向三（差异化标签）：把游戏化追踪做成"轻 RPG 叙事工具"
- **做什么**：好感度/道具/心境 + 时间线，做成可复用的 `.tavern-schema.json` 模板市场；降低非开发者创建门槛（面向 TODO 中的"AI 插件创作层"）。
- **为什么**：G4 是全矩阵空白；它是"功能"而非"内容生态"，正好避开与猫箱/星野拼内容资源的正面战场。
- **验证**：遥测统计状态表使用率与模板复用率；若某类模板（如好感度）使用率显著，围绕它做引导性模板。

### 不做什么（战略取舍）
- **不做内容生态/角色卡商城**：与猫箱/星野拼 UGC 内容，资源不对称，且违背"零侵入"理念。
- **不追 ST 全量扩展生态**：RAG/翻译/生图/TTS 等扩展是 ST 的存量优势，追平成本极高；只做与移动端强相关的子集。
- **不做云账号体系**：与离线隐私定位冲突。

## 6. 风险与威胁

| 风险 | 说明 | 应对 |
|---|---|---|
| **ST 官方或强势第三方推出原生移动端** | SillyDroid 等已出现，若 ST 官方整合，G1 空白将被填 | 速度优势：提前占据心智；差异化绑定 G2/G4，不止于"兼容" |
| **商业 App 开放角色卡导入** | 猫箱等若支持外部卡导入，会截流部分轻量用户 | 守住"可导出 + 可控制 + 离线"三件套，重度用户迁移成本仍高 |
| **国内合规红线** | 无审核内容 + 无上架渠道（GitHub 分发）是当前保护，但也是天花板 | 保持 GitHub/APK 分发路线；内容责任在用户侧，不做内置引导（符合 COMPAT-DATA 铁律） |
| **插件生态差距** | .mtplugin 生态 vs ST 扩展体系 | 定位"受控游戏插件"而非"通用扩展"，差异化而非对标 |
| **单人维护带宽** | 兼容面扩大带来维护压力 | 复用架构守卫与自动化测试（现有 622 项）；按 G1→G3→G4 顺序收敛范围 |

---

## 7. 结论

Mobile Tavern 的差异化不靠"做得比谁多"，而靠**占据一个没人站的位置：移动端原生、SillyTavern 数据全兼容、100% 离线、带轻量游戏化**。竞品分析给出三条清晰路径：主攻兼容深度（G1）、建立隐私护城河（G2）、打出游戏化标签（G4）——三者都建立在已有能力之上，不需要新的战略方向，只需要聚焦与叙事。
