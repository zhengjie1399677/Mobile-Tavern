# 会话管理器与用户人设设计

> 设计状态：已完成  
> 实现状态：阶段一、阶段二已完成；阶段三、阶段四待实现
> 更新时间：2026-08-28  
> 本文是会话管理器、收藏备份、单会话导出以及聊天内用户人设入口的当前权威设计。后续实现与讨论以本文为准；此前仅完成的历史列表视觉原型不代表功能已经完成。

状态标记说明：

- **已完成**：仓库中已经存在并可继续复用的能力；
- **需替换**：已有能力可用，但当前界面或交互不再采用；
- **待实现**：本文已经确定设计，代码尚未完成。

## 一、设计目标

会话管理器必须真正负责会话管理，而不是只展示历史记录。它需要解决以下问题：

- 用户可以快速找到并继续已有会话。
- 普通会话不能被直接删除，必须先归档。
- 重要会话可以收藏；收藏行为会立即生成一份可恢复的独立备份。
- 收藏后的原会话继续变化时，不自动覆盖备份，只提示备份已经落后。
- 会话可以独立导出。
- 用户可以在聊天内管理和切换多个人设，但人设不与角色卡、会话、消息或世界书强关联。
- 角色首页控制台仍显示角色与会话数量，但必须保持紧凑、简约。
- 默认界面使用主题提供的纯色背景，不增加渐变、环境光或预设装饰；自定义 CSS 仍可覆盖界面。

## 二、固定产品决策

### 2.1 会话管理器只有三个一级分类

```text
全部 / 收藏 / 已归档
```

- **全部**：展示尚未归档的原始会话，包含已经收藏的原会话。
- **收藏**：展示收藏时生成的独立备份，不是简单的星标筛选。
- **已归档**：展示已经归档、暂时不再出现在“全部”中的原始会话。

收藏备份与原始会话是两个不同对象。收藏备份可以指向仍然存在的原会话，也可以在原会话被删除后独立存在。

### 2.2 只有归档后的原会话可以删除

- “全部”与“收藏”中不提供删除原会话的入口。
- 普通会话必须先执行“归档”。
- 只有“已归档”页面允许永久删除原会话。
- 永久删除必须二次确认，并明确说明会删除消息、摘要、记忆状态、附件引用和 Agent Journal 等会话数据。
- 若该会话存在收藏备份，删除原会话不会默认删除收藏备份。
- 删除收藏备份使用“取消收藏并删除备份”语义，不得顺带删除原会话。

这套流程以“归档”作为删除前的显式安全缓冲，不再新增回收站分类。

### 2.3 收藏等于立即保存独立备份

点击“收藏”时必须立即生成当前会话的完整可恢复备份。只有备份成功后，收藏操作才算完成。

收藏备份至少包含：

- 会话元数据与标题；
- 全部权威消息 Content Parts；
- 摘要、变量与状态表快照；
- Runtime Plugin 私有会话状态；
- 分支来源信息；
- 会话引用的附件字节；
- 该会话的 Agent Journal；
- 恢复会话所需的角色卡快照或等价可恢复信息；
- 会话中实际使用过的用户人设快照；
- 用户人设的切换记录及其生效边界。

收藏备份不得包含 API Key、访问令牌、全局设置、未在该会话中实际使用过的用户人设或其他会话无关数据。

### 2.4 收藏后不自动更新备份

收藏完成后，原会话仍可继续聊天。以下行为会使收藏备份变为“未更新”：

- 新增用户消息或助手消息；
- 编辑、删除或重新生成消息；
- 创建、替换或回溯会话分支；
- 更新摘要、变量或状态表；
- 切换当前用户人设；
- 更新当前会话正在使用的人设版本；
- 修改会话中影响恢复结果的其他持久化数据。

系统不得在上述行为后自动重建收藏备份，避免每轮聊天产生高成本复制和写入。

界面只显示状态提醒：

```text
备份已保存
```

或：

```text
备份未更新 · 原会话已有新内容
[更新备份]
```

用户点击“更新备份”后才用原会话当前状态替换旧收藏备份。替换必须先完整生成新备份，成功后再切换版本，失败时继续保留旧备份。

### 2.5 会话可以独立导出

单会话导出入口至少存在于：

- 原会话的 `···` 操作菜单；
- 会话详情页；
- 收藏备份的操作菜单。

导出时需要区分：

- **导出当前会话**：导出原会话的最新状态。
- **导出收藏备份**：导出收藏时或最后一次手动更新时保存的版本。

只有收藏备份处于“未更新”状态时，导出操作才提示“该备份不是原会话的最新版本”。备份状态为“已更新”时不显示这项提示，避免重复打扰。

首个实现应提供 Mobile Tavern 原生可恢复会话包；兼容 SillyTavern 的文本历史格式可以作为后续附加导出格式，但不能取代完整会话包。

## 三、会话管理器信息架构

### 3.1 顶栏

```text
会话管理器                              搜索  管理

[ 全部 ]       [ 收藏 ]       [ 已归档 ]
```

- 顶栏不放大面积图标卡。
- 搜索默认收起；点击后顶栏切换为搜索输入状态。
- “管理”进入多选模式。
- 三个分类固定在一行，使用轻量选中状态，不使用厚重描边或渐变。

### 3.2 全部

“全部”按以下顺序展示尚未归档的原会话：

1. 最近继续的会话；
2. 今天；
3. 昨天；
4. 七天内；
5. 更早。

每条会话默认只展示：

- 角色头像；
- 会话名称；
- 角色名称；
- 最后一条消息的单行预览；
- 最近活动时间；
- 收藏状态或“备份未更新”状态。

回合数、字数、摘要数、运行 Profile 等技术信息不在普通列表常驻展示，统一进入会话详情。

### 3.3 收藏

收藏页展示独立备份卡片：

```text
Lina Schneider 的新会话                 已保存
Lina Schneider · 备份于今天 10:42
```

原会话继续变化后：

```text
Lina Schneider 的新会话                 未更新
Lina Schneider · 原会话已有 6 条新消息
```

收藏备份支持：

- 打开对应原会话（原会话仍存在时）；
- 更新备份；
- 从备份恢复为一个新会话；
- 导出收藏备份；
- 取消收藏并删除备份。

原会话已经被删除时，收藏卡片显示“原会话已删除”，但仍可恢复或导出。

### 3.4 已归档

已归档会话支持：

- 恢复到“全部”；
- 重命名；
- 查看详情；
- 导出当前会话；
- 永久删除。

若会话具有收藏备份，归档卡片需要显示备份是否存在及是否落后。永久删除原会话时默认保留收藏备份。

## 四、会话列表交互

### 4.1 单条操作

点击会话主体直接进入或继续聊天。点击 `···` 打开操作菜单。

“全部”中的操作：

- 继续对话；
- 重命名；
- 收藏／查看收藏备份；
- 更新收藏备份（备份落后时）；
- 查看详情；
- 查看平行宇宙；
- 导出当前会话；
- 归档。

“收藏”中的操作：

- 打开原会话；
- 更新备份；
- 从备份恢复；
- 导出收藏备份；
- 取消收藏并删除备份。

“已归档”中的操作：

- 恢复会话；
- 重命名；
- 查看详情；
- 导出当前会话；
- 永久删除。

不使用侧滑操作，避免移动端误触。

### 4.2 多选管理

点击“管理”后进入显式多选模式。

- “全部”：批量收藏、批量归档、批量导出。
- “收藏”：批量更新备份、批量导出备份、批量取消收藏。
- “已归档”：批量恢复、批量导出、批量永久删除。

“全选”必须指当前搜索和筛选结果，不能只选择已经渲染在屏幕上的记录。分页条件下应由应用用例查询全部匹配 ID。

### 4.3 搜索与筛选

搜索必须覆盖权威数据，不能只搜索当前已水合的消息数组。

首期最低搜索范围：

- 会话名称；
- 角色名称。

全文消息搜索需要独立搜索索引后再开放，禁止以不完整结果冒充全文搜索。

筛选项：

- 角色；
- 创建时间；
- 最近活动时间；
- 是否存在分支；
- 收藏备份状态（已更新／未更新）。

排序项：

- 最近活动；
- 最早创建；
- 会话名称；
- 回合数量。

“按角色排列”放进筛选或排列面板，不作为长期占据页面高度的常驻分段控件。

## 五、会话详情与聊天内快捷面板

### 5.1 会话详情

会话详情展示：

- 会话名称与重命名入口；
- 角色卡；
- 创建时间与最近活动时间；
- 回合数、字数和摘要数；
- 分支数量与父分支信息；
- Runtime Profile／Composition Snapshot 摘要；
- 收藏备份状态与更新时间；
- 继续对话、更新备份、导出、归档等操作。

“平行宇宙”必须是详情页中的完整大入口，不放成难以发现的顶栏小图标。

### 5.2 聊天内快捷面板

聊天顶栏的“会话”按钮继续打开紧凑功能菜单。会话管理相关区域提供：

- 会话管理器；
- 当前角色最近会话；
- 平行宇宙；
- 新增的“人设”入口。

完整的收藏、归档、批量管理和搜索仍进入全局会话管理器，不全部塞进聊天内菜单。

### 6.1 入口位置

在聊天顶栏“会话”菜单中新增一项：

```text
人设                                      >
```

该入口与“会话管理器、运行诊断、故事年表、记忆词典”等功能处于同一菜单。按钮使用普通菜单行样式，不放到拥挤的聊天顶栏上单独占据大按钮。

### 6.2 人设结构维持三个字段

每个人设只包含：

```ts
interface UserPersona {
  id: string;
  name: string;
  avatar?: string;
  description?: string;
}
```

- `name`：界面名称为“人设名称”。
- `avatar`：界面名称为“头像”，允许玩家上传、更换或移除自定义头像。
- `description`：界面名称为“人设内容”，使用较大的自由文本框，可以填写任何用户希望作为人设提供的内容。

“人设内容”是界面唯一采用的名称，不使用含义过弱的“详情”，也不把它拆成背景、性格、外貌或其他固定分类。

不得新增以下产品字段或强制分类：

- 身份类型；
- 职业、性别、年龄等固定字段；
- 角色卡与用户人设的绑定关系。

为了让收藏备份、导出和恢复能够重现会话当时实际使用的人设，底层允许保存不可变的人设快照和切换记录。它们属于恢复数据，不在产品界面中命名为“身份”，也不把用户永久绑定到某个会话或角色卡。

人设编辑界面保持简单，只展示人设名称、头像、人设内容，以及保存／取消操作。不得显示 base64、Data URL、资源 ID 或文件路径等技术值。

头像区域采用 72–80px 的可视预览，提供“上传头像／更换头像”和“移除”操作。新实现应通过本地资源能力保存头像引用，避免继续把大段 base64 塞入 settings；迁移时必须继续识别现有 `avatar` 中的 base64 或 Data URL，直到旧数据被安全转换。

### 6.3 人设管理能力

进入“人设”后可以：

- 查看现有多个人设；
- 选择当前使用的人设；
- 新增人设；
- 修改人设名称、头像与人设内容；
- 删除不再需要的人设；
- 选择“不使用人设”。

新增人设本身不自动切换当前人设；用户需要明确点击“使用此人设”或“保存并使用”。

#### 人设列表

人设管理使用独立页面，不再用下拉选择器兼任管理器：

```text
用户人设                                      ＋ 新建
用于聊天时向模型说明“我是谁”

当前使用
[头像]  人设名称                         已使用
        人设内容摘要，最多两行……

其他人设
[头像]  人设名称                            使用
        人设内容摘要，最多两行……
```

- 每行只保留头像、名称、最多两行内容摘要和一个明确的使用状态；
- 点击整行进入编辑，点击“使用”只负责切换；
- 删除入口放入编辑页的次级危险操作区或更多菜单，不与“新建”并排；
- “不使用人设”作为列表中的普通选择项，不伪装成一个额外人设；
- 空状态只解释用途并提供“新建人设”，不展示教程式大卡片。

#### 新建与编辑页

移动端采用随窗口展开的完整页面；若使用 Dialog，也必须接近全高并随可视区域变化，不能复用截图中狭窄的小表单卡片。

```text
‹ 返回                新建人设 / 编辑人设

             [头像预览]
          上传头像 / 更换头像   移除

人设名称
[                                      ]

人设内容
[                                      ]
[          可自由填写任何内容          ]
[                                      ]

                         取消   保存
```

- 人设内容区使用页面剩余空间，最小高度不低于 12 行；
- 头像为空时显示中性占位符，不自动生成花哨插画；
- 保存按钮使用当前主题的 `primary`，不硬编码绿色或其他业务外颜色；
- 编辑现有人设时可以提供“保存”和“保存并使用”；新建默认只保存；
- 离开存在未保存修改的页面时需要确认；
- 键盘弹出后，名称、内容和底部保存操作仍应能滚动到可见区域。

### 6.4 已开始对话时的确认

若当前会话已经存在实际对话内容，以下操作必须先提示并等待用户确认：

- 切换为另一个人设；
- 切换为“不使用人设”；
- 修改当前正在使用的人设内容；
- 删除当前正在使用的人设并导致当前人设变化。

推荐提示文案：

```text
当前对话已经开始。更改人设只会影响之后发送的内容，不会修改已有对话。确定更改吗？
```

按钮：

```text
取消 / 确认更改
```

以下行为不需要该提示：

- 新增一个尚未启用的人设；
- 编辑当前未使用的人设；
- 浏览人设列表但不进行切换。

生成回复期间禁止切换或修改当前人设，避免一次请求中途发生 Prompt 状态变化。

### 6.5 不与角色卡或世界书强关联

当前选择的人设不是会话的固定归属。用户可以在会话过程中自由切换；会话只记录实际发生过的人设快照、切换时间和生效消息边界，用于准确备份、导出和恢复。该记录不限制之后的选择，也不在会话管理器中把会话描述为“属于某个人设”。

首期不要求每条消息重复保存完整人设或增加消息级强引用。可以使用会话内的切换事件描述“从哪一条后续消息开始使用哪个人设快照”，避免在每条消息中复制大文本。

对于角色卡世界书中已经包含的 user 人设内容：

- 不自动识别；
- 不尝试匹配现有人设；
- 不自动合并或去重；
- 不因检测到类似内容而禁用当前用户人设；
- 不修改角色卡或世界书数据。

也就是说，Prompt 组装继续按各自已有的启用规则处理用户人设与世界书。两者可能同时存在，当前版本接受这种结果，不建立隐式关联。

通用 AI 助手默认“不使用人设”，继续保持无角色人设、无预设提示词的纯 API 直连行为。只有用户明确选择人设后，才允许人设内容进入对应请求链路。

### 6.6 与收藏、备份和导出的边界

- 收藏会话时，备份必须包含该会话实际使用过的全部人设快照和切换记录。
- 收藏后继续发送消息，备份标记为“未更新”。
- 切换人设、更新当前会话使用的人设版本、编辑历史消息或创建分支，也都标记为“未更新”。
- 系统不自动重建备份，只显示状态提醒和“更新备份”按钮。
- 导出当前会话时，导出当前最新状态，并携带当前会话实际使用的人设快照与切换记录。
- 导出收藏备份时，导出该备份保存时的版本。
- 只有收藏备份处于“未更新”状态时，才提示“该备份可能不是原会话的最新版本”；状态为“已更新”时不提示。
- 恢复收藏备份时恢复会话内的人设快照与切换历史，但不强制覆盖应用当前选中的全局人设。
- 导入会话不得覆盖已有的同名用户人设；快照作为会话恢复数据保留，是否另存到用户人设列表由用户主动决定。

这保证了会话能够准确还原，同时仍与角色卡、世界书和全局人设列表保持松耦合。

## 七、角色首页紧凑控制台

角色首页仍需显示角色和会话数量，但不再使用占据大量高度的独立统计卡。

推荐形式：

```text
Mobile Tavern Lite                         ＋
本地角色与会话

6 个角色 · 12 个会话
```

也可以与标题副信息合并为一行：

```text
Mobile Tavern Lite          6 角色 · 12 会话
```

约束：

- 统计只占一行；
- 不为角色数和会话数分别制作大卡片；
- 不增加渐变、发光或装饰性背景；
- 数字必须来自会话统计用例，不能以当前分页已经加载的数组长度代替总数；
- 收藏备份不重复计入“会话”数量；
- 会话数量包含未归档与已归档的原会话，不包含已经永久删除的原会话。

## 八、建议数据模型

### 8.1 原会话目录字段

```ts
interface ChatSessionDirectoryMetadata {
  lifecycle: "active" | "archived";
  updatedAt: number;
  archivedAt?: number;
  favoriteBackupId?: string;
  contentRevision: number;
  lastMessagePreview?: string;
}
```

- 旧会话迁移后默认 `lifecycle: "active"`。
- `updatedAt` 优先使用最后一条权威消息时间，缺失时回退 `createdAt`。
- `contentRevision` 在影响恢复结果的会话写入成功后单调递增。
- `lastMessagePreview` 只是有限长度的目录投影，不取代 messages Store 的权威正文。

### 8.2 收藏备份字段

收藏备份必须物理分轨，不塞入 `sessions` 大对象。

```ts
interface FavoriteSessionBackupMetadata {
  id: string;
  sourceSessionId?: string;
  sourceRevision: number;
  sourceUpdatedAt: number;
  createdAt: number;
  updatedAt: number;
  title: string;
  characterName: string;
  integrityHash: string;
}
```

备份状态通过原会话与备份版本比较得出：

- 原会话不存在：`source_missing`；
- `contentRevision === sourceRevision`：`current`；
- `contentRevision > sourceRevision`：`outdated`。

备份字节、附件和恢复载荷进入独立 Backup Store 或独立数据库，不得重复写入全局 settings。

### 8.3 会话人设恢复记录

人设自由文本可能较大，不重复写入会话元数据或每条消息。建议使用独立、可复用的不可变快照：

```ts
interface UserPersonaSnapshot {
  id: string;
  sourcePersonaId?: string;
  sourceRevision?: number;
  name: string;
  avatar?: string;
  description?: string;
  createdAt: number;
}

interface SessionPersonaChange {
  id: string;
  sessionId: string;
  personaSnapshotId?: string;
  effectiveAfterMessageId?: string;
  changedAt: number;
}
```

- `personaSnapshotId` 缺失表示从该边界起不使用用户人设。
- 快照保存人设名称、头像引用和人设内容，不派生身份类型或固定结构字段。
- 切换记录是恢复事实，不是角色卡、人设与会话之间的永久绑定。
- 收藏备份与单会话导出只携带目标会话引用到的快照。

### 8.4 跨库安全语义

收藏备份可能涉及主数据库、附件数据库和 Agent Journal 数据库，不能伪装成单个 IndexedDB 原子事务。

收藏或更新备份必须遵循：

1. 从权威 Store 读取一致的会话快照；
2. 写入新的临时备份版本；
3. 校验引用、字节完整性和哈希；
4. 成功后切换收藏元数据指针；
5. 最后回收旧版本；
6. 任一步失败时继续保留旧备份，并明确显示失败。

## 十、完成条件

- 未归档会话在任何入口都不能直接永久删除。
- 原会话归档后才出现永久删除操作。
- 收藏成功时已经存在一份经过完整性校验的独立备份。
- 收藏后的聊天变化只产生“备份未更新”提醒，不自动更新备份。
- 手动更新备份失败时旧备份仍可恢复。
- 原会话删除后收藏备份仍可导出和恢复。
- 单会话能够导出为版本化、可校验的完整会话包。
- 搜索不会把未加载消息造成的不完整结果冒充全文搜索。
- 聊天菜单可以进入人设管理，并能新增、编辑和切换人设。
- 人设编辑严格只有人设名称、头像和一个大的人设内容文本框。
- 已开始对话时更改当前人设必须经过确认。
- 会话备份与导出包含实际使用过的人设快照和切换记录。
- 切换人设或更新当前会话使用的人设版本后，已有收藏备份变为“未更新”。
- 只有导出未更新的收藏备份时才提示它不是最新版本。
- 人设不与角色卡或世界书建立强关联，也不自动匹配世界书内容。
- 通用 AI 助手在用户未主动选择人设时继续保持纯 API 直连。
- 角色首页可以看到准确的角色数和会话总数，统计区域只占一行。
