> 设计状态：已完成
> 实现状态：阶段一已完成，阶段二至五待继续
> 更新时间：2026-08-29
> 本文是“新建主题、编辑自定义主题、主题预览”界面的权威产品设计。主题包格式、安全边界、CSS 能力和受限交互规则仍以 [主题与界面扩展开发指南](Theme_Development_Guide.md) 为唯一权威来源，本文不重复定义运行时协议。

## 一、状态标记

- **已完成**：仓库中已经存在并可复用的底层能力；
- **需替换**：能力存在，但当前交互或视觉不再沿用；
- **待实现**：产品设计已经确定，代码尚未完成。

当前问题不是底层能力不足，而是把面向主题作者的技术字段一次性挤进了移动端小弹窗。重构目标是重新组织复杂度，不删除高级能力。

## 三、固定设计决策

### 3.1 使用完整工作区，不使用底部小弹窗

“新建主题”和“编辑主题”进入独立的全屏页面，统一命名为“主题工作室”。

- 手机：完整页面，顶部导航，底部固定主要操作；
- 平板和宽屏：左侧编辑、右侧预览的双栏布局；
- 横屏和键盘弹出时按实际可视高度重排；
- Android 返回键等同于页面返回，并参与未保存修改确认；
- 不把核心编辑器限制在固定高度的 Bottom Sheet 中。

### 3.2 默认主题起点必须朴素

新建主题不预置紫色、发光、渐变、玻璃或媒体背景。用户首先选择一个起点：

```text
新建主题

[从当前主题创建]    保留当前视觉作为起点
[浅色基础]          中性纯色背景
[深色基础]          中性纯色背景
[高级空白主题]      仅供熟悉主题包的作者使用
```

推荐项是“从当前主题创建”。所有基础模板使用主题定义的纯色背景；图片、视频、环境光和渐变只能由用户后续主动添加或通过自定义 CSS 实现。

### 3.3 普通模式与高级模式分层

普通模式用于完成绝大多数视觉调整，高级能力继续存在但不常驻占据空间。

- 普通模式：主题信息、基础外观、核心颜色、预览；
- 高级模式：完整语义变量、自定义 CSS、媒体、状态与交互、主题包元数据；
- 高级模式不是另一个主题类型，切换不会丢失数据；
- 已导入的高级主题即使包含普通模式无法表达的内容，也必须可以打开、保存和导出，不能被简化器静默覆盖。

## 四、新建主题流程

### 4.1 第一步：选择起点

四种起点以纵向轻量列表呈现，每项只使用名称、单句说明和小型预览色块，不使用大幅宣传图。

### 4.2 第二步：填写主题信息

普通用户只需要填写：

- 主题名称：必填；
- 主题说明：可选。

`schemaVersion` 根据是否使用 Theme 1.1 能力自动决定；主题包 `version` 默认生成并在普通模式中隐藏。高级作者可以在“高级信息”中修改版本，但不能改出非法值。

完成后进入主题工作室。此时只创建编辑草稿，不立即覆盖现有主题，也不立即应用到全局界面。

## 五、主题工作室信息结构

移动端不再用四个窄 Tab 横向挤压。首页使用四个清晰的编辑分区：

```text
‹ 返回                 主题工作室
  暮色                         未保存

[预览当前草稿]

外观          明暗、圆角与基础观感             >
颜色          核心颜色与高级语义颜色           >
自定义 CSS    精确影响任意现有 UI              >
交互与媒体    本地媒体、状态与触发规则          >

                   保存主题   保存并应用
```

点击分区进入对应的全尺寸子页面。顶部始终显示主题名称和草稿状态；底部主要操作遵守 Safe Area。

### 5.1 外观

外观页只提供可立即理解的选项：

- 基础模式：浅色／深色；
- 圆角：直角、轻微、标准、柔和四个预设；
- 高级圆角：展开后允许输入合法 CSS 长度；
- 主题名称与主题说明的编辑入口。

首期不新增底层尚不支持的“界面密度”伪配置。若以后增加密度，必须先定义稳定变量和所有组件的统一响应规则。

### 5.2 颜色

默认只展示五个核心颜色：

1. 页面背景；
2. 内容表面；
3. 主要文字；
4. 强调色；
5. 边框。

每项使用颜色色块、名称和当前值组成一行。点击后打开颜色选择器，同时支持粘贴合法的 HSL 通道值。由核心颜色推导出的颜色先展示实时结果，但不在用户确认前覆盖已经手工修改的高级变量。

“高级颜色”折叠区展示完整语义变量，并按用途分组：

- 页面与表面；
- 文字与弱化内容；
- 主要、次要与强调操作；
- 输入、边框与焦点；
- 危险操作；
- 对话与长文本。

编辑器对文字/背景、按钮文字/按钮背景等关键组合给出对比度提示。提示只说明可读性风险，不强制阻止保存。

### 5.3 自定义 CSS

自定义 CSS 使用接近全屏的代码编辑区，不再放在十几行高的普通文本框中。

必须提供：

- 行号、当前行列和基础语法高亮；
- 保存前校验与行列级错误提示；
- 稳定 `data-ui` 选择器快捷参考；
- 常用片段插入，如聊天背景、消息气泡、底栏和对话框；
- 搜索；
- “清空 CSS”二次确认；
- 独立的预览入口。

自定义 CSS 仍允许最大程度影响当前 UI。安全清洗、作用域和禁止项继续遵守主题开发指南；编辑器不能因为提供可视化选项而削弱已存在的 CSS 能力。

### 5.4 交互与媒体

默认使用三个顺序清晰的分区：

```text
媒体资源
状态
触发规则
```

媒体资源通过本地资源库选择，显示名称、类型、循环、音量、静音和适配方式等适用项，不要求用户手写资源 ID。

状态编辑器按 boolean、enum、counter 创建字段，只显示对应类型需要的选项。

触发规则使用句式化编辑：

```text
当 [进入聊天页]
并且 [允许主题媒体]
执行 [播放：雨声]
然后 [显示背景：车站视频]
```

- 每个事件、条件和动作只能从运行时白名单中选择；
- 不提供 JavaScript 输入；
- 冷却时间、仅执行一次和延迟放入“更多设置”；
- 缺失资源或失效引用在规则行内标出；
- “高级 JSON”允许查看和编辑完整 Theme 1.1 数据，并复用现有严格校验；
- 可视化编辑器无法无损表达的未来字段必须保留在草稿中，不得静默删除。

## 六、预览设计

### 6.1 预览不直接劫持整个应用

编辑中的草稿不应在无边界提示的情况下永久染色整个应用。手机点击“预览当前草稿”后进入临时全屏预览，顶部保留明确的“返回编辑”与“应用中：未保存草稿”；宽屏则在右侧预览容器中显示。

退出预览后恢复进入工作室前的主题。只有“保存并应用”才改变正式启用主题。

### 6.2 内置预览场景

预览至少提供四个场景，避免只看抽象色块：

- 角色页：标题、角色卡、底栏；
- 聊天页：顶栏、长短消息、输入区；
- 菜单与对话框：列表、弹窗、主次按钮和危险操作；
- 表单：输入框、开关、选择器和错误提示。

场景使用固定演示数据，不读取或暴露用户真实聊天。预览容器必须使用真实主题变量、`data-ui` 契约和 CSS 作用域，不能另做一套与实际界面不一致的假样式。

媒体和交互预览遵守当前“允许主题播放本地媒体”权限；未授权时显示静态占位和说明，不自动索取权限。

## 七、保存、应用与离开

编辑器顶部使用一个短状态：

```text
未保存 / 验证失败 / 已保存
```

底部操作：

- “保存主题”：保存草稿，但不改变当前正在使用的主题；
- “保存并应用”：校验、保存并切换到该主题；
- “放弃修改”只放在返回确认中，不常驻为与保存同权重的大按钮。

保存按钮使用当前宿主主题的 `primary` 颜色，不硬编码紫色、绿色或橙色。验证失败时留在当前分区，滚动并聚焦第一个错误，同时保留全部草稿。

存在未保存修改时，返回、Android 返回键和关闭页面都显示：

```text
主题还有未保存的修改。
继续编辑 / 放弃修改
```

## 八、主题管理页

“设置 → 外观与显示”中的主题管理只负责选择与管理，不承担编辑器本体：

```text
主题
当前：系统浅色

内置主题
[系统浅色] [系统深色]

我的主题                                      ＋ 新建
[主题色块] 暮色                         已应用
           简短说明                    ···

导入主题
```

自定义主题的更多菜单包含：应用、编辑、复制、导出、删除。删除当前主题前必须先选择回退主题；删除不应放在卡片正面。

导入和导出继续使用 `.tavern-theme.json`。若主题引用当前设备的本地资源，导出时必须提示这些引用不会自动携带资源文件，不能让用户误以为主题包包含媒体。

## 九、视觉约束

- 默认使用当前主题的纯色 `background` 与 `card`，不自行增加渐变或环境光；
- 不用多层卡片包裹每一个字段，优先采用分组标题、行和轻量分隔线；
- 页面左右边距建议 16px，组间距 20–24px；
- 触控目标不小于 44×44px；
- 主按钮只保留一个强视觉层级，其他操作使用次级或文字按钮；
- 危险操作只使用主题的 destructive 语义色；
- 所有颜色、圆角和阴影来自当前宿主主题，编辑草稿只影响预览容器；
- 任何固定底部操作都必须避让 Safe Area 和软键盘；
- 文案优先面向普通用户，`Schema`、资源 ID、HSL 通道和 JSON 只在高级模式出现。

## 十、实施结构

### 阶段一：工作室外壳与草稿

- **已完成**：建立全屏主题工作室和响应式编辑/预览双栏框架；
- **已完成**：将编辑草稿与正式启用主题分离，预览不再切换应用根主题；
- **已完成**：实现未保存状态、离开确认、保存和保存并应用；
- **已完成**：保持旧 Theme 1.0/1.1 主题包导入、编辑和稳定 ID 兼容。

### 阶段二：外观与颜色

- 实现起点选择和基础模板；
- **已完成**：实现核心颜色、完整语义颜色与圆角预设；
- 实现高级值无损保留和对比度提示。

### 阶段三：真实场景预览

- 建立四类固定预览场景；
- 实现手机临时全屏预览和宽屏侧栏预览；
- 验证进入、退出和取消时正式主题不被污染。

### 阶段四：CSS 编辑体验

- 接入代码编辑、搜索、选择器参考和片段；
- 把清洗与校验错误映射到行列；
- 覆盖窄屏、长 CSS 和软键盘场景。

### 阶段五：交互与媒体构建器

- 建立媒体、状态、触发规则三个编辑器；
- 提供高级 JSON 往返编辑并保证未知兼容字段不丢失；
- 验证资源缺失、媒体权限关闭和旧 Theme 1.0 的降级。

### 阶段六：替换旧编辑器

- 从主题管理入口切换到主题工作室；
- 完成旧草稿和已保存主题的兼容验证后移除旧 Bottom Sheet；
- 补齐移动端返回键、Safe Area、焦点、屏幕阅读器和自动化回归测试。

## 十一、完成条件

- 新建主题不再在狭窄 Bottom Sheet 内完成；
- 用户无需理解版本号、Schema、原始 CSS 变量或 JSON，也能创建和调整普通主题；
- 高级作者仍能完整使用自定义 CSS、全部语义变量和 Theme 1.1 能力；
- 新主题默认是纯色基础视觉，不擅自加入渐变、环境光、媒体背景或指定品牌色；
- 编辑草稿不会污染当前正式主题，取消或退出能完整恢复；
- 预览至少覆盖角色、聊天、菜单/对话框和表单四种真实场景；
- 旧主题包能够无损打开、保存、应用和导出；
- 普通模式不能静默删除其无法表达的高级字段；
- 本地资源缺失或媒体权限关闭时可明确降级，主题其他样式仍然可用；
- 手机、横屏、平板、软键盘、Safe Area 和 Android 返回键均可正常使用；
- 所有保存失败都保留草稿并定位错误，不出现无反馈丢失；
- 视觉层级简洁，主界面不再呈现后台配置表式的密集卡片堆叠。
