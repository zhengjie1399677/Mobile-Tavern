## 一、定位：中间态产品

- Mobile Tavern 是「标准 / 协议时代到来之前」的中间态产品，不自认能定义或推动成熟协议。
- 不扛「定义标准」的旗，也不退回「内容 + 订阅」的传统软件路线。
- 产品在协议 / 标准成熟后会被自然取代（乐观估计约三年内），这是已知且接受的结局，不影响当前投入。

## 二、核心定性：底座是唯一核心，其余都是插件

- 核心永远只是一个可扩展的底座。
- SillyTavern 兼容（角色卡、预设、世界书、MVU、Regex、TavernHelper、兼容 iframe）**只是一个插件**
  ——虽然现在已经有人在用，但它是「一个插件」，不是核心功能。
- 底座哲学：未来不需要聊天软件，每个人都可以自由定义自己的一切；往后只会是一种协议、一种标准
  （类似 SillyTavern 角色卡标准）。底座正是为此投入。

## 三、两条路线

1. **继续支撑 SillyTavern 兼容**：包括可安装兼容 Silly 的插件，已有人在用。
2. **继续插件化、底座化**：让底座从「潜力」变成「可玩」。

两条路线不冲突：路线一（兼容）是路线二（底座）之上的一个插件；路线二才是主航道。

## 四、明确不做

- 不内置角色卡（做卡麻烦且不盈利）。
- 不运营社区（社区已关闭）。
- 不做国产星野 / Character.AI 式竞品，不做订阅 / 抽卡游戏化，不做 B2B 平台。
- 不定义 / 推动标准或协议。

## 五、能力发展方向（整体性设计，非单点功能）

「缺内容」的答案 = 把底座的自由定义能力从「潜力」变成「可玩」：缺的是支撑娱乐化和工具化的
**能力 / 插件生态**（VSCode 类比：底座 + 大量插件），而非垂直 1 对 1 剧情内容。

三个方向：

1. **能力积木层**：联网、图像、TTS、日历、记忆写入等外部工具实例。底座已有 Tool Registry 与
   External Tool Plugin 框架，缺口在工具实例数量与来源治理（签名 / 可信来源 / 官方 SDK）。
2. **自定义闭环**：定义 Agent = 选角色 + 挂工具 + 调行为，可存、可改、可文件级分享。
3. **扩展通道**：SDK + 官方示例，兑现底座扩展性。

## 六、阶段 0 契约清点结论

已具备的可分享积木：角色卡、预设、主题、`.mtplugin`、`.mttool`、Table Memory Schema、统一备份 v6。

缺口三样：工具实例太少、Profile 不可导出（缺粘合剂）、无 SDK / 示例。

Host Protocol、生态、标准均为远期，不作为当前目标。

## 七、法律定位优势（保留）

本地优先 + BYOK；不生成内容、不存对话（仅本地 IndexedDB），天然规避平台内容责任。
